Branch: `claude/zealous-sagan-8aa4gb` · Scope: all 22 routers in `src/app.ts` MOUNTS, all services/jobs, schema + 44 migrations, `scripts/migrate.js`, docs. Method: full walk of every router, diff of `OrgEventType`/`NotifType`/`WEBHOOK_EVENT_TYPES` unions vs emit/create sites, diff of `PERMISSION_CATALOG` vs every `requirePermission`/`perms.has` site, migration-dir vs registry diff.

## Executive summary — top 10 actionable items (severity × effort)

1. **[Data-loss / runtime 500] Fractional leave days cannot be persisted — half-day approval and the accrual engine both write floats into `Int` columns.** `LeaveBalance.total_days`/`used_days` are `Int` (`prisma/schema.prisma:415-416`), but approval increments `used_days` by `working_days` which is `Float` (0.5 half-days, 0.1–0.99 mid-shift leave — `src/routes/leave.ts:229-232`), and the monthly accrual job writes `days_per_year/12` rounded to 2dp (`src/services/leaveAccrual.ts:82,94`). Prisma rejects non-integer values on `Int` fields, so approving a half-day leave throws inside the transaction and any accrual rate not divisible by 12 (e.g. 20/yr → 1.67/mo) fails for every user, every month. Fix: migrate both columns to `DECIMAL(5,2)`/`Float`. One migration, high blast radius.

2. **[Broken endpoint] Bulk shift assignment can never succeed** — `bulkAssignmentSchema` requires `assignments: [{user_id, shift_id, date}]` (`src/schemas/index.ts:209-212`) but the handler reads `user_ids`, `shift_id`, `dates` (`src/routes/shifts.ts:450-453`). A body matching the schema fails the handler's `user_ids array required` check; a body matching the handler 422s at validation. The schema's `dry_run` flag is also unimplemented.

3. **[Cross-tenant IDOR] Four write/read paths missing org scoping**:
   - `PUT /performance/goals/:id` updates any goal in any org — `prisma.performanceGoal.update({where:{id}})` with no org filter (`src/routes/misc.ts:329`).
   - `POST /performance/goals` never validates `user_id`/`review_id` belong to the caller's org (`src/routes/misc.ts:296-303`).
   - `GET /performance/reviews/:userId/insights` loads the user, reviews, goals and 90 days of attendance with **no org check at all** (`src/routes/misc.ts:340-360`) — cross-org PII exfiltration to the Anthropic API and the caller.
   - `PUT /leave/balance/:userId` looks up the balance by `user_id` only — no org filter and no target-user org check (contrast the GET above it, which checks) (`src/routes/leave.ts:400-403`).

4. **[Secret leak] `GET /org/settings` returns the raw Organisation row to every authenticated org member** — including `wa_access_token` (WhatsApp Cloud API bearer token) and `admin_notes` (platform-admin internal notes) (`src/routes/misc.ts:635-641`). The dedicated `GET /org/whatsapp` endpoint carefully redacts the same token (`misc.ts:822`); the settings endpoint undoes that. Also unlocked: any employee can read office IPs/SSIDs, rates, policies.

5. **[Privilege escalation] `POST /users/import` skips every safeguard `POST /users` has** — no zod validation, no `VALID_ROLES` check, no `org.roles.manage` gate for admin-tier roles: `role: u.role || 'employee'` (`src/routes/users.ts:502-507`). Any holder of `employees.import` (HR admin) can mass-create `super_admin` users — or users with a garbage role string. Import also skips onboarding auto-assign and `seats_limit` (which is never enforced anywhere — see §1.7).

6. **[Money] Payroll ignores the overtime-rules engine and drops manual adjustments on regeneration.** `POST /payroll/generate` and the auto-generate cron hardcode `overtime * rate * 1.5` (`src/routes/payroll.ts:107`, `src/jobs/scheduler.ts:576`) — `OvertimeRule` rows (daily/weekly/seventh_day, per-rule multipliers) and `Shift.overtime_multiplier` are consumed **only** by the read-only `/overtime/summary`. Worse, generate's upsert recomputes `gross_pay` **without** `manual_adjustment` (`payroll.ts:109,116`), so re-running generation after an expense reimbursement silently removes the reimbursement from gross/net while the claim stays `reimbursed` and `manual_adjustment` still shows the amount. The cron variant additionally omits the unpaid-leave deduction the route applies (`scheduler.ts:570-586` vs `payroll.ts:96-109`).

7. **[Money / atomicity] Expense reimbursement is not transactional and ignores currency.** Payroll update and claim update are two separate writes (`src/routes/expenses.ts:223-239`) — a crash in between leaves pay increased with the claim still `approved` (double-reimbursable). A claim in EUR is added at face value to a USD payroll record with no conversion or mismatch check (`expenses.ts:208`).

8. **[Ops] `prisma/migrations/20260622000000_wa_log_error` is not registered in `scripts/migrate.js`** (registry at `scripts/migrate.js:151-192` lists 43 of 44 dirs) — fresh deploys never get the `whatsapp_notification_logs.error_message`/`attempts` columns and every WA-log write will fail.

9. **[RBAC drift] Permission catalog vs enforcement is out of sync in both directions.** `platform.audit.view` and `platform.broadcast.send` are checked (`src/routes/admin.ts:22,534`) but absent from `PERMISSION_CATALOG` — they're never seeded, `platform_admin`'s `allKeys().filter(platform.*)` never includes them, and any attempt to grant them violates the FK on `permissions.key`; the routes only work via the `platform.orgs.manage` fallback, and can never be delegated to a `platform_assistant`. Conversely `org.settings.view` and `reports.view` are cataloged and seeded but enforced nowhere (settings GET is open to all; reports gate only on `reports.export`).

10. **[Perf / integrity] No index supports the hottest new query patterns.** `attendance_records` has only the `(user_id, date)` unique — every scheduler tick (`org_id, date` scans ×4 jobs), `/attendance/today`, late-summary (`org_id, date>=x, late_minutes>0`), and analytics loops seq-scan the biggest table. Also missing: `users(org_id)`, `leave_requests(org_id, status)` and `(user_id, status, start_date, end_date)` (probed on **every check-in/checkout/heartbeat**), `payroll_records(org_id, period_year, period_month)`, `refresh_tokens(expires_at)` (no cleanup job either), `whatsapp_notification_logs(org_id, created_at)`.

## 1. Incomplete features

1.1 **NotifType union has 6 members no code ever creates**: `attendance_checkin`, `attendance_checkout`, `remote_request`, `remote_no_reply`, `payslip_ready`, `shift_reminder` (`src/services/notifications.ts:60-72` vs all `createNotification` sites). Payslip-ready and shift reminders go WhatsApp-only (`src/routes/payroll.ts:325-330`, `src/jobs/scheduler.ts:488`) — users without phone numbers get nothing in-app. Conversely, two types are created that are **not in the union**: `'announcement'` (bypasses typing via raw `createMany` in `src/services/announcements.ts:56` and `src/routes/admin.ts:560`). Overtime approve/reject have **no in-app notification at all** (WhatsApp only, `src/routes/overtime.ts:108-110,136-138`), and there is no `swap_requested`/`swap_approved` notification anywhere.

1.2 **Outbound webhooks have no update/rotate/re-enable lifecycle.** `src/routes/org-webhooks.ts` is create/list/delete/test only — no PUT to change the events list, no secret rotation, and once a hook auto-disables at 20 failures (`webhookDelivery.ts:24`) the only recovery is delete + recreate with a new secret. No cap on hooks per org. The webhook payload is only `{event, org_id, timestamp}` — no entity id, so receivers must re-poll everything.

1.3 **Roadmap promises vs code**: ROADMAP #14 promises a "device/session list endpoint" alongside refresh rotation — none exists (no way to list or revoke individual sessions; only logout-all via `revokeAllForUser`). ROADMAP #16/#17 are marked open but OpenAPI generation (`src/services/openapi.ts`) and prom-client metrics (`src/utils/metrics.ts`) shipped; #30 payroll lock/recall marked ☐ but shipped — the docs are stale in both directions.

1.4 **Dead schema columns**: `Shift.min_rest_hours` is written by shift CRUD but enforced nowhere (no rest-period validation on assignment or publish — ROADMAP #35 confirms deferred, yet the column and schema field ship and accept input, implying function). `ShiftBreak.reminder_after_mins` and `deduct_if_skipped` are persisted (`src/routes/shifts.ts:86-87`) but no job reads them (no break reminder, no skipped-break deduction). `RemoteSession.ai_summary` is never written. `AttendanceRecord.ip_checkout_pending_at` has no writer in `src/`.

1.5 **Corrections**: approving a correction that creates a fresh record sets `status:'in'` even when only a checkout time was supplied (`src/routes/corrections.ts:158-166`) — a permanently "checked-in" historical record. Approval updates only `check_in_at/check_out_at/hours_worked` — `net_hours_worked`, `late_minutes`, `early_out_minutes`, `adherence_score`, `status` are left stale, so a corrected check-in still counts as "late" in late-policy points and the adherence score, and payroll (which prefers `net_hours_worked`, `payroll.ts:92`) **ignores corrected hours whenever `net_hours_worked` was already set**. No employee cancel/withdraw endpoint for a pending correction (leave has one, corrections and expenses don't).

1.6 **Onboarding**: `OnboardingTask.due_date` exists and sorts lists, but nothing scans for overdue tasks — no reminder/escalation job (contrast documents' expiry scan). Template PUT delete-and-recreates items with no effect on in-flight tasks (documented, fine) but there is no way to un-assign / cancel a checklist assigned by mistake.

1.7 **`seats_limit` is written by platform admin (`src/routes/admin.ts:216`) and displayed, but never enforced** — `POST /users`, `/users/import`, and org registration all skip it. A "seats" concept that bills but doesn't meter.

1.8 **Holidays**: no PUT/update endpoint (delete + recreate only, `src/routes/holidays.ts`), no bulk import of national calendars, and `holidays.ts:4-6` claims "four engines" but only leave working-days and the absent detector consume holidays (see §2.1).

1.9 **Payroll month windows use server-local time** (`startOfMonth`/`endOfMonth`, `src/utils/auth.ts:80-86`) while attendance `date` values are UTC-anchored org-local days — first/last-day records can fall into the wrong payroll month for orgs far from server TZ.

## 2. Cross-feature integration holes

2.1 **Holidays don't reach the late engine, shift scheduling, or payroll.** The absent detector skips holidays (`src/jobs/scheduler.ts:211-213`) but the **late-arrival detector does not** (`scheduler.ts:73-195`) — on a public holiday every employee with a shift is marked `late`, managers get "X is 30 min late" WhatsApp/in-app alerts, and HR gets 60-min escalations. Shift assignment warns on leave overlap but not holidays (`src/routes/shifts.ts:339-342`); the shift-reminder job pings employees for shifts on holidays; leave-approval's attendance-marking loop skips weekends but not holidays (`src/routes/leave.ts:240`); payroll has no holiday-pay concept.

2.2 **New modules emit no org events → SSE and outbound webhooks are blind to them.** `OrgEventType`/`WEBHOOK_EVENT_TYPES` cover only 6 scopes (`src/services/notifications.ts:14-20`, `src/schemas/index.ts:356-363`). Documents, onboarding, kudos, announcements, holidays, payroll (generate/process/recall), user lifecycle, and org-settings changes emit nothing — `emitOrgEvent` call sites exist only in attendance/expenses/shifts(swaps)/overtime/leave/corrections. An integrator cannot subscribe to `payroll_processed`, `document_added`, or `employee_created` — the highest-value events for a Deel/Rippling-class integration surface. SSE clients likewise get no INVALIDATE for any of the new modules and fall back to the 15-s count poll.

2.3 **Who's-out feed omits absences and corrections context**: `GET /org/whos-out` (`src/routes/misc.ts:708-744`) returns approved leave + remote + holidays but not employees marked `absent` (scheduler-created records) — a manager checking "who's away" doesn't see no-shows; there is no combined read model with attendance status.

2.4 **Accrual engine vs onboarding defaults**: new users get hardcoded balances (annual 20 / sick 10 / wfh 5 — `src/routes/users.ts:320-329` and again in import) regardless of the org's `leave_accrual` policy; mid-year joiners then also receive full monthly increments with no pro-rating or join-date awareness (`leaveAccrual.ts:72-99` iterates all active users uniformly).

2.5 **Expense → payroll linkage is one-directional**: reimbursement mutates payroll, but payroll recall/regenerate does not un-reimburse or flag affected claims (see exec #6); `ExpenseClaim.reimbursed_in_payroll_id` has no index and no payroll-side view listing which claims are inside a record.

2.6 **Presence challenge vs WhatsApp prefs**: `notification_prefs` (check_in, late_alerts, …) are stored per user (`schema.prisma:103`) but never consulted by `createNotification` or the WhatsApp `notify*` helpers — grep shows no reader of `notification_prefs` outside the prefs endpoints themselves. The whole preference feature is write-only.

2.7 **OpenAPI**: `buildOpenApiDoc(MOUNTS)` does walk every mounted router (`src/app.ts:120-163`) ✓ — but documents no query parameters (pagination/filters invisible), no permission requirements, and `GET /notifications/stream` (SSE) and `/health`, `/metrics`, `/openapi.json` are absent; the three hand-written `API_*.md` docs at repo root are now redundant and drifting.

## 3. Consistency drift (new vs old routers)

3.1 **Zod coverage is bimodal** (mutations validated / total): corrections 3/3, expenses 4/4, payroll 4/4 vs **admin 0/17, admin-platform-users 0/3, org-rbac 0/6, misc/performance 0 (announcements only), leave 1/5, users 3/10, shifts 8/17, notifications 0/3, public 0/1**. Ad-hoc `req.body` destructuring in the old routers means no 422 field errors, no OpenAPI request bodies, and unvalidated types (`admin.ts` plan/subscription PATCHes accept arbitrary `features_override` JSON).

3.2 **Pagination**: opt-in `page/limit` implemented on users, leave requests, kudos, admin orgs, notifications, WA logs, audit logs — but corrections and expenses hard-cap at `take: 200` with no paging (`corrections.ts:106`, `expenses.ts:100`), shifts/swaps/overtime lists return everything unbounded, `GET /payroll` unbounded, `/attendance/report/export` unbounded JSON.

3.3 **Audit coverage**: new modules audit well (corrections, expenses, documents, onboarding, kudos, webhooks, holidays). **Not audited**: all of org-rbac (role create/permission replace/user role assignment — the most security-sensitive mutations in the app, `src/routes/org-rbac.ts`), user grants replace (`users.ts:135-176`), user create/update/deactivate incl. credential changes, org settings (incl. tax/pension rate changes that alter pay math), office IPs/SSIDs, shifts/assignments/swaps, overtime approve/reject, leave approve/reject, all of admin.ts (plan/subscription/suspend), platform-user CRUD.

3.4 **`String(req.params.x)` normalization** is used in all new routers, while older ones cast (`req.params.id as string`) — cosmetic but shows the sweep stopped: `payroll.ts`, `shifts.ts`, `overtime.ts`, `users.ts`, `admin.ts` still use `as string`.

3.5 **Permission-gating style**: three patterns coexist — `requirePermission()` middleware, inline `req.permissions?.has()` (users credentials), and inline `resolveUserPermissions()` re-fetch (documents/kudos/onboarding/goals do a second DB round-trip per request even when middleware already resolved). `admin.ts` additionally hard-gates on `role !== 'platform_admin'` (`admin.ts:9-12`) making the `platform_assistant` role unable to reach even its permitted routes through this router — assistants can never use `/admin/*` despite holding `platform.orgs.view`/`platform.blog.manage`.

3.6 **Envelope adherence** is good (ok/created/paginated everywhere); exceptions: `notifications/stream` raw SSE (by design) and `public/blog/:slug` 404 shape is hand-rolled (`public.ts:95`).

3.7 **Scope semantics of "team" permissions are inconsistent**: `documents.view_team` and `onboarding.view_team` actually grant **org-wide** read of any user's documents/checklists (`documents.ts:167-183`, `onboarding.ts:211-226`), while `attendance.view_team`, `leave.view_team`, `employees.view_team` restrict to direct reports. A line manager can read any employee's contracts/IDs org-wide.

## 4. Security / tenancy

4.1 **Cross-tenant gaps** — see exec #3 (performance goals ×2, AI insights, leave balance PUT). Everything else checked scopes correctly (documents, kudos, onboarding, corrections, expenses, webhooks, holidays, shifts, swaps all filter `org_id`).

4.2 **Secrets**: `JWT_SECRET`/`JWT_REFRESH_SECRET` fall back to `'dev-secret'`/`'dev-refresh-secret'` with no production fail-fast (`src/utils/auth.ts:5-6`, `auth.ts:22`, `refreshTokens.ts:7`). `GET /org/settings` leaks `wa_access_token` (exec #4). SSO Redis-down fallback redirects with **tokens in the query string** (`src/routes/auth.ts:515`). SSE still accepts `?token=` (self-documented log-leak risk, `notifications.ts:13-18`).

4.3 **Session lifecycle**: password change blacklists only the current access token — refresh-token families of *other* devices survive a password change (`auth.ts:318-341`; no `revokeAllForUser`). Deactivating a user (`users.ts:455-472`) revokes nothing — their access token works until expiry (8h default) and only refresh is blocked (`auth.ts:246` checks `is_active`). Platform-user soft-delete likewise leaves tokens alive.

4.4 **Rate limits**: only global 100/min + auth 20/15min. No specific limiter on: CSV/report generation (`/reports/:type`, `/attendance/report/export` — S3 uploads + full-table scans), the 4 Anthropic-proxy endpoints (`/analytics/chat`, `/anomalies`, `/payroll-anomalies`, `/shifts/ai-schedule` — direct paid-API spend per request), presigned upload-URL minting, `/public/onboard` (org-application spam), broadcast. Kudos has its own nice 20/day cap — the pattern exists but wasn't applied where it costs money.

4.5 **Presence is fully client-attested**: `ip`/`ssid` in heartbeat and ip-event bodies are client-supplied and matched against office lists (`attendance.ts:1271,1315`) — nothing verifies the claim (the FCM challenge only proves the device is awake, not on-network). Known design tradeoff (ROADMAP #37), worth restating as the legal-time-record risk.

4.6 **CSV formula injection**: `csvExport.ts` quotes but does not escape leading `=+-@` in user-controlled fields (names, reasons, notes) — opening exports in Excel executes formulas.

4.7 **`GET /attendance/:userId`** allows any `attendance.view_team` holder to read **any** org member's 90-day history, not just their reports (`attendance.ts:1584-1604`) — inconsistent with `/attendance/today` which restricts to direct reports.

## 5. Data integrity

5.1 **Int columns receiving fractions** — exec #1 (leave balances). Same class of issue: `LeaveRequest.working_days` was migrated to FLOAT but balances were forgotten.

5.2 **Missing indexes** — exec #10. Additionally `expense_claims.reimbursed_in_payroll_id`, `onboarding_tasks(due_date)` (future overdue scans), `announcements(scheduled_for)` for the 5-min publisher (`published_at IS NULL AND scheduled_for <= now` scans full table).

5.3 **Soft-delete filtering**: `deleted_at` honored consistently for documents/kudos/onboarding templates ✓, but **users**: `misc.ts` performance reviews `where.user_id in team` path doesn't exclude deleted users' reviews; `announcementAudienceWhere` ✓; nothing ever sets `users.deleted_at` inside org flows (only platform-admin delete) — org-level "remove employee" is only `is_active=false`, so email uniqueness blocks re-inviting a departed employee's address forever.

5.4 **Money in JS floats**: the entire payroll pipeline computes in `Number` then stores to `Decimal` with no rounding discipline (`recalcPayrollTotals`, generate loops) — penny drift accumulates across tax/pension multiplications; `.toFixed(2)` only applied to hours, never to currency amounts.

5.5 **Unpaid-leave deduction over-counts cross-month leave**: generate sums `working_days` of any unpaid leave *overlapping* the month (`payroll.ts:96-103`) — a leave spanning two months is deducted in full in both.

5.6 **Department uniqueness**: `@@unique([org_id, name, parent_id])` with nullable `parent_id` — Postgres treats NULLs as distinct, so duplicate top-level department names are only blocked by the app-level check (`departments.ts:82-85`), which races.

5.7 **`OrgHoliday` recurring collision**: `@@unique([org_id,date])` means a recurring "Dec 25 2026" blocks adding "Dec 25 2027" as a one-off with a different name; recurrence is expanded at read time only, fine, but the create dup-check (`holidays.ts:31-34`) doesn't consider recurring expansion.

5.8 **Swap approval doesn't check `status === 'pending'`** (`shifts.ts:664-681`) — re-approving an approved swap swaps the shifts back while still reporting success; reject after approve also possible. Swap create never validates `target_id` equals the target assignment's `user_id`.

## 6. Ops / quality

6.1 **Migration registry** — exec #8 (`wa_log_error` unregistered).

6.2 **Jobs in `startAllJobs`** (`scheduler.ts:790-808`): all 15 defined jobs are registered ✓. Missing jobs: refresh-token table purge (rows accrete forever; only `revoked_at` is set, never deleted), in-app notification retention purge, announcement receipts/audit-log retention, onboarding overdue reminders, WA-log retention.

6.3 **In-memory state in jobs**: `_shiftReminderSent` Set (`scheduler.ts:454`) grows unbounded, resets on restart (duplicate reminders), and is per-instance (the Redis tick-lock prevents same-minute double-fire but not post-restart re-sends).

6.4 **`leave_accrual: { not: undefined }` and `late_policy: { not: undefined }`** (`leaveAccrual.ts:58`, `latePolicy.ts:146`) are no-op filters in Prisma (undefined = ignored) — both jobs scan **all** orgs each run; intended `not: null`.

6.5 **Sequential awaits in hot jobs**: late detector does per-user awaited updates across all orgs every minute; payroll generate does per-user attendance queries in a loop (N+1); `analytics/attendance-trend` issues one query per day (30 queries/request).

6.6 **Test coverage holes on money paths**: `src/__tests__/unit` covers pure services (accrual math, late policy, payroll *utils*) but there are **zero route/integration tests** — payroll generate/adjust/recall/process, expense reimburse, leave approve balance-decrement (the very path broken by exec #1), correction approval, checkout math have no test executing the Prisma layer where the Int/Float bug lives. 21 unit files, all `__mocks__`-based.

6.7 **`unhandledRejection` is logged but not exited/alerted** (`server.ts:55-57`); errorHandler logs via `console.error` bypassing pino (`errorHandler.ts:38`).

6.8 **Docs drift**: ROADMAP status ~1 sprint stale (see §1.3); root-level `API_DOCUMENTATION.md`/`API_REFERENCE_DETAILED.md`/`TECHNICAL_API_SPEC.md` predate the expansion and contradict the generated OpenAPI.

## 7. Missing features worth adding (ranked)

1. **Session/device management** — list + revoke individual refresh-token families (`GET/DELETE /auth/sessions`). Rides on: `RefreshToken.family_id` already persisted per device; promised in ROADMAP #14 and un-shipped.
2. **Payroll approval chain + payment export** — a `pending_approval` state between generate and process, plus bank/CSV (SEPA/ACH-style) payment file export. Rides on: existing status machine (draft→processed→recalled), `csvExport.ts`, audit trail.
3. **Time-off revocation** — cancel an *approved* leave with balance refund and attendance-record cleanup (currently impossible; balance and `leave`-status records are permanent). Rides on: the existing approve transaction inverted + `recordAudit`.
4. **Org-event catalog expansion + delivery log** — add `payroll_processed`, `document_added`, `employee_created/updated`, `onboarding_completed`, `holiday_changed` to `OrgEventType`/`WEBHOOK_EVENT_TYPES`, include `entity_id` in payloads, persist an `OrgWebhookDelivery` table with retry/backoff. Rides on: `emitOrgEvent` bus + `webhookDelivery.ts` fanout already in place.
5. **Geofence / rotating-QR kiosk punch** (ROADMAP #37) — deliberate punch layer so WiFi presence isn't the sole legal time record. Rides on: existing QR service (`qrcode.ts` already rotates org codes), `check_in_type` enum, mobile FCM channel.
6. **Scheduled-vs-actual labor cost & timesheet approval** — weekly manager sign-off of timesheets before payroll consumes them (Deputy-style). Rides on: `adherence_score`, `scheduled_start/end` already stored per record; corrections flow is the dispute path.
7. **Open shifts & availability** (ROADMAP #35) — `ShiftAssignment.user_id` nullable "open" rows + employee claim endpoint + rest-period validation using the already-stored `min_rest_hours`. Rides on: swaps machinery for approval.
8. **Document e-signature / acknowledgement** — "sign contract" onboarding items: an `acknowledged_at` on `EmployeeDocument` + onboarding item type `document`. Rides on: documents vault + onboarding tasks + receipts pattern from announcements.
9. **Per-employee compensation history** — effective-dated `hourly_rate` changes (currently a single mutable column; historical payroll regeneration silently uses the *current* rate). Rides on: audit trail already captures before/after; needs a `CompensationChange` table payroll reads by period.
10. **Public API keys / PATs with scopes** — `api_access` is already a plan feature key (`constants/rbac.ts:10`) with nothing behind it. Rides on: permission catalog for scopes, `requirePermission` middleware, rate-limit infra.
